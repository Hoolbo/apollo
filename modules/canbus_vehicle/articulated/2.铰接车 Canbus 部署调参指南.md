# 铰接车 Canbus 部署调参指南

本文档指导你在工控机上部署铰接车 Canbus 模块时，需要检查和修改的所有参数。

---

## 1. CAN 硬件配置

### 1.1 确认 CAN 接口

在工控机上确认 CAN 接口名称：

```bash
ip link show type can
```

通常为 `can0`。如果你的接口名不同（比如 `can1`），需要配置对应的 channel。

### 1.2 设置 CAN 波特率

前车 FCBee2 和后车 Hunter SE 必须使用相同的波特率。根据实车确认后设置：

```bash
sudo ip link set can0 type can bitrate 500000    # 常见值：250000 或 500000
sudo ip link set can0 up
```

### 1.3 验证 CAN 通信

启动 Apollo 前先确认能收到两台车体的帧：

```bash
candump can0
```

你应该能看到以下 CAN ID 的帧（前车反馈 + 后车反馈）：

| CAN ID | 来源 | 说明 |
|---|---|---|
| `0x23C` | 前车 | 驱动电机反馈 |
| `0x22C` | 前车 | 转向反馈 |
| `0x20C` | 前车 | VCU 通用状态 |
| `0x221` | 后车 | 运动反馈 |
| `0x211` | 后车 | 底盘状态 |

如果只看到前车或只看到后车的帧，检查 CAN 线连接和终端电阻。

## 2. 需要修改的配置文件

### 2.1 车辆物理参数

**文件**: `modules/common/data/vehicle_param.pb.txt`

```protobuf
vehicle_param {
  brand: ARTICULATED
  vehicle_id {
      other_unique_id: "articulated"
  }
  front_edge_to_center: 0.50    # ← body_length / 2 = 1.00 / 2
  back_edge_to_center: 0.50     # ← body_length / 2
  left_edge_to_center: 0.33     # ← body_width / 2 = 0.66 / 2
  right_edge_to_center: 0.33    # ← body_width / 2
  length: 1.00                  # ← front_body.body_length
  width: 0.66                   # ← front_body.body_width
  height: 0.0                   # ← 未定义
  min_turn_radius: 0.0          # ← 未定义
  max_acceleration: 3.0         # ← cilqr vehicle.json acc_max
  max_deceleration: -3.0        # ← cilqr vehicle.json acc_min
  max_steer_angle: 2.0944       # ← EPS 电机最大角度 120° (rad)
  max_steer_angle_rate: 0.0     # ← 未定义
  steer_ratio: 6.0              # ← EPS电机角度 / 前轮角度（实测约6）
  wheel_base: 0.60              # ← front_body.wheelbase
  wheel_rolling_radius: 0.0     # ← 未定义
  max_abs_speed_when_stopped: 0.1
  brake_deadzone: 0.0
  throttle_deadzone: 0.0
}
```

**关键参数说明**：

| 参数 | 影响 | 来源 |
|---|---|---|
| `max_steer_angle` | Steer() 中 EPS 限幅 | EPS 电机物理极限 120° = 2.0944 rad |
| `steer_ratio` | Steer() 前轮角→EPS角；chassis() EPS角→前轮角 | 实测 EPS 电机角度 / 前轮转角 ≈ 6.0 |
| `wheel_base` | Planning 曲率计算 | 两个 vehicle.json `front_body.wheelbase` = 0.60 m |
| `max_acceleration` | Planning 速度约束 | cilqr vehicle.json `acc_max` = 3.0 m/s² |

### 2.2 Canbus CAN 卡配置

**文件**: `modules/canbus/conf/canbus_conf.pb.txt`

```protobuf
vehicle_parameter {
  brand: ARTICULATED
  max_enable_fail_attempt: 5
  driving_mode: COMPLETE_AUTO_DRIVE
}

can_card_parameter {
  brand: SOCKET_CAN_RAW        # ← CAN 卡类型
  type: USB_CARD                # ← 接口类型
  channel_id: CHANNEL_ID_ZERO  # ← can0 对应 ZERO, can1 对应 ONE
  num_ports: 8
  interface: NATIVE
}

enable_debug_mode: false
enable_receiver_log: false      # ← 调试时可设为 true 查看接收帧
enable_sender_log: false        # ← 调试时可设为 true 查看发送帧
```

**需要改的场景**：

| 场景 | 修改 |
|---|---|
| CAN 接口不是 `can0` 而是 `can1` | `channel_id: CHANNEL_ID_ONE` |
| 使用 USB-CAN 适配器（如 EmUCan） | `brand: HERMES_CAN` 或对应品牌 |
| 使用 PCI-E CAN 卡 | `type: PCI_CARD` |
| 调试时想看 CAN 收发日志 | `enable_receiver_log: true` / `enable_sender_log: true` |

### 2.3 Canbus 启动参数

**文件**: `modules/canbus/conf/canbus.conf`

```bash
--flagfile=modules/common/data/global_flagfile.txt
--canbus_conf_file=modules/canbus/conf/canbus_conf.pb.txt
--load_vehicle_library=/opt/apollo/neo/lib/modules/canbus_vehicle/articulated/libarticulated_vehicle_factory.so
--load_vehicle_class_name=ArticulatedVehicleFactory
--enable_chassis_detail_pub          # ← 必须开启，发布 Articulated 详细消息
--enable_chassis_detail_sender_pub
--chassis_debug_mode=false
--use_control_cmd_check=false        # ← 关闭标准 ControlCommand 校验
--use_guardian_cmd_check=false       # ← 关闭 Guardian 校验
--noreceive_guardian                 # ← 不接收 Guardian 消息
--estop_brake=30.0
```

**一般不需要改**，除非：

| 场景 | 修改 |
|---|---|
| .so 安装路径不同 | 修改 `--load_vehicle_library` 路径 |
| 不想发布 ChassisDetail | 删除 `--enable_chassis_detail_pub` |

## 3. 不需要修改的文件

| 文件 | 说明 |
|---|---|
| `modules/canbus/dag/canbus.dag` | 框架 DAG，加载 `CanbusComponent`，与车型无关 |
| `modules/canbus/launch/canbus.launch` | 启动脚本，与车型无关 |
| `articulated/*.cc/h` 所有协议代码 | CAN 报文定义由 DBC 决定，不需要改 |
| `articulated_vehicle_factory.cc/h` | 车辆工厂逻辑，不需要改 |
| `articulated_message_manager.cc/h` | 报文注册，不需要改 |

## 4. 部署步骤

### Step 1: 编译

```bash
# 进入 Apollo 容器
aem enter

# 编译铰接车模块（会自动编译依赖的 proto）
buildtool build -p modules/canbus_vehicle/articulated
```

### Step 2: 配置 CAN 接口

```bash
# 在容器外执行（需要 root 权限）
sudo modprobe can
sudo modprobe can_raw
sudo ip link set can0 type can bitrate 500000
sudo ip link set can0 up
```

### Step 3: 检查 CAN 通信

```bash
# 确认能收到前后车反馈帧
candump can0 -t a | head -50
```

### Step 4: 启动 Canbus

```bash
# 在 Apollo 容器内
cyber_launch start modules/canbus/launch/canbus.launch
```

### Step 5: 验证

```bash
# 查看标准 Chassis 消息（前车信息）
cyber_monitor
# 找到 /apollo/canbus/chassis 查看 speed_mps, steering_percentage

# 查看完整 ChassisDetail（前后车全部信息）
# 找到 /apollo/canbus/chassis_detail 查看 Articulated 消息
```

## 5. 常见问题排查

### Q: 启动后 cyber_monitor 看不到 chassis 消息

1. 检查 `canbus.conf` 中 `--load_vehicle_library` 路径是否存在：
   ```bash
   ls /opt/apollo/neo/lib/modules/canbus_vehicle/articulated/libarticulated_vehicle_factory.so
   ```
2. 检查日志：
   ```bash
   cat /opt/apollo/neo/data/log/canbus.INFO | tail -50
   ```

### Q: chassis 消息有但速度始终为 0

1. 用 `candump can0 | grep 23C` 确认前车驱动电机反馈帧 `0x23C` 存在
2. 检查 `enable_receiver_log: true` 后的日志，确认 Parse 被正确调用

### Q: 后车不响应运动指令

1. 确认后车处于 CAN 控制模式（查看 `chassis_detail` 中 `rear_chassis_status_529.control_mode`）
2. 确认 `EnableAutoMode` 被成功调用（查看日志中 `Switch to COMPLETE_AUTO_DRIVE mode ok`）
3. 用 `candump can0 | grep 111` 确认 `0x111` 帧有在发出且数据非全零

### Q: 前后车 CAN ID 是否冲突？

不冲突。前车 ID 范围 `0x20C-0x23C`，后车 ID 范围 `0x111-0x421`，无交集。

## 6. 调参 Checklist

部署到新工控机时，按此清单逐项确认：

- [ ] CAN 接口名称（`can0` / `can1`）→ `canbus_conf.pb.txt`
- [ ] CAN 波特率与实车一致 → `ip link set` 命令
- [ ] `candump` 能看到前后车反馈帧
- [ ] `vehicle_param.pb.txt` 中的物理尺寸与实车一致
- [ ] `max_steer_angle` 和 `steer_ratio` 与前车 EPS 规格一致
- [ ] `canbus.conf` 中 `.so` 路径正确
- [ ] 编译成功，`libarticulated_vehicle_factory.so` 已生成
- [ ] `cyber_launch start` 后 `cyber_monitor` 能看到 chassis 和 chassis_detail
